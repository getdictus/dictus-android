# Onboarding

A first launch walks through seven steps inside the onboarding shell (#196, iOS `OnboardingShell`), in iOS's order (#200): welcome, language (#198), adding and selecting the keyboard, the wait for the model (only while it is not on disk), the microphone (only while not granted), a first dictation, and « C'est prêt ». A passed-over step keeps its segment of the bar, which reads as done. The shell draws a dashed progress bar of five segments (language to first dictation; none on the welcome and completion screens), a back chevron on the language step, a large title, a blue pill button and a « Passer » row under it on the first dictation (« Pas maintenant » on the microphone, #220).

- **ID:** `onboarding`
- **Tier:** Gratuit
- **Statut Android:** partiel (no Pro scenes, no What's new)
- **Screens:** `app.onboarding.welcome`, `app.onboarding.language`, `app.onboarding.ime-setup`, `app.onboarding.model-preparation`, `app.onboarding.microphone`, `app.onboarding.first-dictation`, `app.onboarding.completion`, `sys.settings.ime`, `sys.ime-picker` — see [screens.md](screens.md)

## Sub-features

- `onboarding.welcome`: the intro carousel (#197, iOS `WelcomePage`): three swipeable pages, each looping the iOS scene video (muted, light or dark render after the app's theme, its still frame until the first frame, for good under « Réduire les animations »): « Parlez. Dictus écrit. » / « Dans toutes vos apps, depuis le clavier. », « Même sans réseau. » / « … Tout se passe sur votre téléphone. », « Dans votre clavier. » / « Dans vos notes, messages ou e-mails : … »; page dots (current page a blue capsule, TalkBack « Page N sur 3 »), « Commencer » on every page. Unlike iOS, the pages do not turn by themselves. — présent
- `onboarding.language`: « Votre langue » (#198, iOS `LanguageSetupPage`), right after the intro, prefilled from the phone's languages (the first one with a Dictus keyboard, else English, as on iOS). One « Dictée et clavier » row (code badge, language name, « Changer » opening the four keyboard languages): dictation follows the keyboard (#292), so there is no separate dictation language. « DISPOSITION DU CLAVIER » AZERTY / QWERTY / QWERTZ, the model line (« Modèle Parakeet 0.6B v3, le meilleur pour votre langue sur ce téléphone. ~N Mo, téléchargés dès que vous continuez. Modifiable dans Modèles. »), and a preview drawn by the keyboard's own `KeyboardView` in the chosen layout. « Continuer » saves the keyboard language and layout (a layout equal to the language's default stays inherited, #134) and starts the recommended model's install in the background (#170 worker). When that tap has just started a download (the model is not on disk, no install runs and the last one did not fail, iOS `startDownloadIfNeeded`), a dialog stays on the step (#304, iOS « Keep Dictus open »): « Le modèle se télécharge », « Le modèle (~N Mo) se télécharge maintenant. Vous pouvez quitter l'app, par exemple pour ajouter le clavier : le téléchargement continue en arrière-plan. » and one button « J'ai compris », which moves on; back and an outside tap do nothing. Unlike iOS it does not ask to stay: the Pixel 4 downloads as fast with Dictus behind. Nothing is saved before « Continuer »; going back to the intro keeps the choices. — présent
- `onboarding.keyboard-setup`: — Spécifique iOS (Full Access); Android's own step is `onboarding.ime-setup`.
- `onboarding.apple-intelligence`: — Spécifique iOS.
- `onboarding.pro-scenes`: — absent.
- `onboarding.smart-mode-pick`: — absent.
- `onboarding.model-download`: the full-screen preparation screen (`app.onboarding.model-preparation`, #181) for the model recommended for the phone's RAM, after the keyboard setup. Passed over when the model is already on disk when the keyboard step moves on (#200, iOS `ModelDownloadPage`). The install starts with « Continuer » on the language step, or when this step opens if it is not running (no « Télécharger »): « On prépare votre modèle », « Téléchargement  N % », « X Mo sur Y Mo », « Le téléchargement continue si vous quittez l'app. », then « Préparation pour ce téléphone » (extraction, verification), « Chargement du modèle » (engine load), « Votre modèle est prêt »; after 1.5 s the step moves on by itself (no « Continuer »). On failure « Le modèle vocal n'a pas pu être préparé » + « Réessayer ». The install runs in a WorkManager foreground worker (#169): it goes on with the screen off or the app in the background, and the step shows its state again when reopened. — présent
- `onboarding.microphone`: Google Play's prominent disclosure (#220): « Microphone », a message saying Dictus records only during a dictation the user starts, to turn it into text, and that the audio and the text never leave the phone; « Autoriser le micro » then the system prompt, or « Pas maintenant » without it. After a refusal: « Sans le micro, la dictée ne peut pas fonctionner. Vous pourrez l’autoriser plus tard dans les réglages Android. » and « Continuer ». « Pas maintenant » and that « Continuer » go to « C'est prêt », passing over the first dictation; « Nouvelle dictée » then asks for the microphone, and a refusal shows the toast « Autorisez le micro pour Dictus dans les réglages Android pour dicter. ». Right before the first dictation (#200, iOS `MicPermissionPage`). Passed over when RECORD_AUDIO is already granted; a denied one is still shown. — présent
- `onboarding.first-dictation`: « Essayez maintenant » (#199, iOS `GlobeKeyTutorialPage` and `FirstDictationStage`): a practice field takes the focus and the keyboard opens with no tap. The subtitle follows the stage: « Votre clavier s'ouvre en dessous. » while it opens; « Touchez le champ pour ouvrir votre clavier » without a keyboard (none within 1 s, or closed with Retour); on another keyboard « Changez de clavier, puis choisissez Dictus. » and a blue « Choisir Dictus » button that opens the system keyboard picker (Android's stand-in for iOS's drawn globe animation); on the Dictus keyboard « Touchez le micro bleu et parlez. Le texte arrive ici. » and a banner « Touchez le micro bleu, puis parlez » ↘. The dictation runs in the keyboard (its waveform, #184). Three characters typed or dictated once Dictus has been up turn the field green with a check and open « C'est prêt » ~0.6 s later. After 15 s on another keyboard without Dictus, « Continuer » shows right of « Passer ». Leaving the step empties « Dernière transcription » (#245). — présent
- `onboarding.stop-standby`: — Spécifique iOS.
- `onboarding.completion`: « C'est prêt » (#199, iOS `OnboardingSuccessView`): the app icon with a green check on its corner (springs in), « Dictus vous attend dans le clavier de chaque app. Un appui sur le micro, et parlez. » (the Android gesture where iOS says the globe), « Commencer » fades in and opens Accueil. — présent
- `onboarding.resume`: the step is written to DataStore by its stable name (`onboarding_step`, #196) on every change and restored on a cold start, after a force-stop or a reboot too; an unknown name starts at the welcome screen, the name of the removed ABC / 123 step (`keyboardLayout`) resumes at the model preparation (#270), `microphone` resumes at the keyboard setup (#200: written by the order before #200, where the microphone came before the keyboard; the name is kept, so a new-order run stopped on the microphone lands there too), and finishing the onboarding writes `welcome` back. — présent
- `onboarding.whats-new`: — absent.
- `onboarding.ime-setup` *(Spécifique Android)*: « Ajouter le clavier »: « Ouvrir les paramètres » (system on-screen keyboards) then « Sélectionner Dictus » (system picker); « Continuer » only once Dictus is enabled and selected.
- `onboarding.default-page` *(Spécifique Android)*: — retired by #270, as iOS removed its layer-choice step (#213). The Réglages choice is retired too (`keyboard.default-page`, #288): the keyboard always opens on letters.

- `onboarding.back` *(shell)*: the chevron at the top left, and the system back, return from the language step to the welcome screen. No step after the language step goes back (the model download has started), as on iOS; there the system back leaves the app, and the next launch resumes on the same step.

## How to get to it (user POV)

1. Install Dictus and open it.
2. « Commencer » → langue → clavier → modèle (si pas encore prêt) → micro (si pas encore accordé) → première dictée → « C'est prêt ».

## Driving it with Argent

Preconditions: a phone where Dictus has **never completed onboarding**. Pierre's Pixel has completed it, and the only way back is clearing the app's data (models, settings, notes' state): **not allowed** on this phone.

- **Reach step 1.** Not reachable on Pierre's Pixel without `pm clear`: report `onboarding` as not driven, with this precondition, unless a disposable device or AVD (`dictus_api35`, headless) is provided.
- **On a fresh install.** `launch.sh` → `READY`; `mcp__argent__await-ui-element {selector:{text:"Commencer"}}` → tap → `Votre langue` → `Continuer` → `Ajouter le clavier` → `Ouvrir les paramètres` / `Sélectionner Dictus` → `Continuer` → `On prépare votre modèle` (unless already on disk) → `Microphone` → `Autoriser le micro` → system dialog → `Essayez maintenant` …
- **Download dialog (#304).** On a fresh install, « Continuer » on `Votre langue` → `await-ui-element {selector:{text:"Le modèle se télécharge"}}` → tap `J'ai compris` → `Ajouter le clavier`. To see it again: `pm clear` (emulator only), since the model is then on disk or downloading.
- **Mic already granted.** `adb shell pm grant dev.pivisolutions.dictus android.permission.RECORD_AUDIO` before the walk: the model wait (or the keyboard step) goes straight to `Essayez maintenant`.
- **Resume.** No helper writes a step into DataStore (a protobuf file): walk to the step, then `adb shell am force-stop dev.pivisolutions.dictus` and relaunch; the same step and the same bar segment come back.
- **Proof.** One capture per step and the final `Accueil` tab in the tree; `has_completed_onboarding` true in `adb shell run-as dev.pivisolutions.dictus cat files/datastore/*.preferences_pb | strings`.

## Gotchas

- To reach the first dictation on the emulator without walking the steps: force-stop the app, write `has_completed_onboarding=false` and `onboarding_step=firstDictation` into `files/datastore/dictus_prefs.preferences_pb` with `run-as`, then `ime set` the keyboard to start on, then launch. Run `ime set` a few seconds after the force-stop: force-stopping Dictus while its keyboard is the current one makes Android fall back to Gboard.
- Clearing data to see onboarding again would delete Pierre's models and settings: never on the Pixel.
- The model step downloads for real (Parakeet 0.6B: a 487 MB archive, ~670 MB installed, from 6 GB of RAM, so on the Pixel 4; Small Q5 ~190 MB below). Parakeet's archive then takes ~3.5 min to extract on the Pixel 4, and every file's SHA-256 is checked before the engine loads it and the step moves on.
- On the emulator (2 GB of RAM) onboarding recommends Small Q5. To drive the Parakeet install there, build with `-Pdictus.parakeetMinRamGb=1` (debug only); the install works, the engine itself does not load on x86_64.
- Logs of an install (`helpers/log.sh`): `Model install started for <key>`, `Download took … ms`, `Extracted <file> (… bytes) in … ms`, `Extraction took … ms`, `Verification took … ms`, `Model install succeeded for <key> in … ms` (or `failed … : <reason>`).
- The keyboard step leaves Dictus for Android's settings and its picker; `MainActivity` re-reads the IME state on return.
- The first dictation records the room, through the Dictus keyboard.
